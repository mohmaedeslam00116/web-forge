# Design Layout — compose content and visual material together

Start from the user's job and the actual information model, then integrate the selected visual world. Do not create a clean typographic skeleton and postpone all real visual content until the end.

## Process

1. Identify the task, content objects, relationships, first decision, and critical states.
2. Load the selected layoutDNA and visualDirection. Confirm the first-screen anchor, media role, graphic language, and responsive treatment.
3. Map primary, supporting, contextual, and optional regions. Choose rows, tables, cards, columns, image fields, galleries, timelines, maps, diagrams, canvases, or open layout according to meaning.
4. Reserve real space for actual media. A hero image, product render, diagram, or gallery is a layout region with a defined crop and purpose—not a late decorative add-on.
5. Define visual rhythm: scale, content pacing, contrast, color fields, dense/quiet regions, and signature devices. Do not make every section a row of cards or a wall of text.
6. Define navigation and interaction by route topology and task frequency.
7. Define responsive transformations for regions, media crops, reading order, data representations, and controls. A mobile screen may need different crops, media, or task sequence.
8. Implement with real content/assets, not generic placeholders. Missing assets must be recorded as dependencies, never silently replaced by unrelated stock.
9. Render and compare the result to the selected concept and asset plan.

## First-viewport test

For Persuade/Experience, the first screen should usually show the subject, product, artwork, scene, or visual proof—not only a heading and buttons. The exception needs a reason in the brief. For Operate/Read, the first screen should show the primary work or content, which may be a table, editor, article, chart, or diagram.

## Validation

Check actual image crops, focal points, loading, line length, data density, scroll rhythm, text-on-image contrast, overflow, RTL, keyboard order, and reduced-motion. If a visual asset is missing, mark it NOT VERIFIED rather than evaluating an empty placeholder as finished.
