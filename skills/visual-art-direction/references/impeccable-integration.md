# External methodology reference: Impeccable

Web Forge studied the public `pbakaus/impeccable` project (Apache-2.0, created by Paul Bakaus) as an external design-engineering reference: https://github.com/pbakaus/impeccable

The most useful ideas to adapt are:

- distinguish Persuade, Operate, Read, and Experience surfaces before deciding how expressive the visual work should be;
- treat a redesign as a replacement visual world rather than a cosmetic midpoint between old and new;
- explore a broader set of material and cultural reference systems before choosing a visual direction;
- use focused critique/refinement passes (such as stronger, color-aware, motion-aware, or delight-oriented passes) rather than one vague "make it better" instruction;
- inspect the rendered browser output and fix what the evidence shows;
- consider extraordinary engineering only when it serves the product: cinematic transitions for a showcase, fast virtualization for data tables, or useful interactive media for a creative tool.

Web Forge does not copy Impeccable's SKILL.md, commands, scripts, or detector. Its skill names, schemas, checker, and workflows are independently authored. Projects that separately install Impeccable may use it as an optional companion, but Web Forge does not require it or assume its CLI/hooks are installed.

When the external skill is present, do not run duplicate workflows blindly. Let Web Forge own product discovery, concept selection, brand-reference provenance, and asset plans; use the companion only for a clearly scoped critique or refinement pass. Preserve the selected Design Passport and re-check after changes.
